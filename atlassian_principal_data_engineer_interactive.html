DSAHash Map / SetD1

First duplicate event ID

Problem: Given event_ids = [101, 205, 301, 205, 410], return the first ID that appears twice.

🐢 Brute force first

Compare each event with every later event. O(n²).

💡 Hint

Remember IDs already processed.

💻 Optimized solution
def first_duplicate(event_ids):
    seen = set()
    for event_id in event_ids:
        if event_id in seen:
            return event_id
        seen.add(event_id)
    return None
⏱ Complexity
O(n) average time, O(n) space.
👑 Principal signal
At scale, ask whether exact dedupe is required, state retention duration, partitioning key, and whether state can expire.
DSAHash Map / SetD2

Two Sum — complement lookup

Problem: nums=[2,7,11,15], target=9. Return the two indices.

🐢 Brute force first

Check every pair: O(n²).

💡 Hint

For current n, calculate needed = target - n. Store number → index.

💻 Optimized solution
def two_sum(nums, target):
    seen = {}
    for i, n in enumerate(nums):
        needed = target - n
        if needed in seen:
            return [seen[needed], i]
        seen[n] = i
    return []
⏱ Complexity
O(n) average time, O(n) space.
👑 Principal signal
Explain why the dictionary value is the index: the key answers “have I seen this number?” and the value answers “where?”
DSASliding WindowD3

Maximum events in any K consecutive buckets

Problem: counts=[10,12,3,20,15,8], k=3. Return maximum sum across any 3 consecutive buckets.

🐢 Brute force first

Sum each size-k slice separately: O(nk).

💡 Hint

Reuse previous window: add entering value, subtract leaving value.

💻 Optimized solution
def max_window(counts, k):
    if k > len(counts):
        return None
    window = sum(counts[:k])
    best = window
    for right in range(k, len(counts)):
        window += counts[right]
        window -= counts[right-k]
        best = max(best, window)
    return best
⏱ Complexity
O(n) time, O(1) extra space.
👑 Principal signal
Connect this to rolling event metrics; in streaming systems, window state and late events become the architecture discussion.
DSASorting / IntervalsD4

Merge overlapping validity windows

Problem: Merge [(1,3),(2,6),(8,10),(9,12)].

🐢 Brute force first

Repeatedly compare all interval pairs until no overlap: potentially O(n²).

💡 Hint

Sort by start, then compare only with the last merged interval.

💻 Optimized solution
def merge_intervals(intervals):
    intervals.sort(key=lambda x: x[0])
    merged = []
    for start, end in intervals:
        if not merged or start > merged[-1][1]:
            merged.append([start, end])
        else:
            merged[-1][1] = max(merged[-1][1], end)
    return merged
⏱ Complexity
O(n log n) due to sorting; O(n) output space.
👑 Principal signal
Very relevant to effective-date ranges, sessionization and slowly changing data windows.
DSAHeap / Top-KD5

Top 3 customers by score

Problem: Given millions of customer scores, return only the top 3.

🐢 Brute force first

Sort all n values: O(n log n).

💡 Hint

Maintain a min-heap of size k.

💻 Optimized solution
import heapq

def top_k(items, k):
    heap = []
    for score, customer in items:
        heapq.heappush(heap, (score, customer))
        if len(heap) > k:
            heapq.heappop(heap)
    return sorted(heap, reverse=True)
⏱ Complexity
O(n log k) time, O(k) heap space.
👑 Principal signal
For distributed data, discuss local top-K then global top-K to reduce shuffle volume.
PandasDedupeP1

Keep latest record per customer

Problem: A DataFrame has customer_id, updated_at, status. Keep only the latest row per customer.

🐢 Brute force first

Loop each customer and manually compare timestamps.

💡 Hint

Sort by timestamp, then drop duplicates keeping last.

💻 Optimized solution
latest = (
    df.sort_values("updated_at")
      .drop_duplicates("customer_id", keep="last")
)
⏱ Complexity
Dominated by sort: roughly O(n log n).
👑 Principal signal
If the table is huge, ask whether upstream data is already partitioned/sorted, whether SQL/Spark is more appropriate, and how ties are resolved.
PandasGroupByP2

Revenue per customer with order count

Problem: Return total revenue and order count for each customer.

🐢 Brute force first

Loop rows and maintain manual dictionaries.

💡 Hint

groupby + agg.

💻 Optimized solution
result = (
    df.groupby("customer_id")
      .agg(
          total_revenue=("amount", "sum"),
          order_count=("order_id", "nunique")
      )
      .reset_index()
)
⏱ Complexity
Conceptually O(n) aggregation plus grouping overhead.
👑 Principal signal
Discuss high-cardinality group keys and whether the workload belongs in Pandas or a distributed engine.
PandasJoinP3

Customers with no matching orders

Problem: Given customers and orders DataFrames, return customers who have no orders.

🐢 Brute force first

For every customer, scan all orders.

💡 Hint

Left merge with indicator, filter left_only.

💻 Optimized solution
x = customers.merge(
    orders[["customer_id"]].drop_duplicates(),
    on="customer_id",
    how="left",
    indicator=True
)

result = x[x["_merge"] == "left_only"]
⏱ Complexity
Hash join style behaviour conceptually near O(n+m), implementation-dependent.
👑 Principal signal
Before joining large frames, project needed columns and reason about one-to-many cardinality to avoid accidental explosion.
SQLWindowS1

Second-highest salary per department

Problem: Return employees with the second-highest distinct salary in each department.

🐢 Brute force first

Correlated subqueries or repeated scans.

💡 Hint

DENSE_RANK partitioned by department.

💻 Optimized solution
WITH ranked AS (
  SELECT
      employee_id,
      department_id,
      salary,
      DENSE_RANK() OVER (
          PARTITION BY department_id
          ORDER BY salary DESC
      ) AS rnk
  FROM employees
)
SELECT *
FROM ranked
WHERE rnk = 2;
⏱ Complexity
Logical cost depends on partitioning/sort; window typically requires ordering within partitions.
👑 Principal signal
Clarify whether “second highest” means distinct salary; DENSE_RANK vs ROW_NUMBER is the key semantic decision.
SQLLatest rowS2

Latest event per entity

Problem: Return the latest event for each entity_id.

🐢 Brute force first

MAX(timestamp) then join back, which can duplicate on ties.

💡 Hint

ROW_NUMBER over entity ordered by event_time desc plus deterministic tie-breaker.

💻 Optimized solution
WITH x AS (
  SELECT
      e.*,
      ROW_NUMBER() OVER (
          PARTITION BY entity_id
          ORDER BY event_time DESC, event_id DESC
      ) AS rn
  FROM events e
)
SELECT *
FROM x
WHERE rn = 1;
⏱ Complexity
Partition + order cost; physical execution engine-dependent.
👑 Principal signal
Always define tie-breaking. In CDC pipelines, event time vs ingestion time vs source sequence matters.
SQLRunning totalS3

Cumulative spend by customer

Problem: For each order, calculate customer cumulative spend ordered by order_time.

🐢 Brute force first

Self-join each row to all previous rows.

💡 Hint

SUM OVER partition and order.

💻 Optimized solution
SELECT
    customer_id,
    order_id,
    order_time,
    amount,
    SUM(amount) OVER (
        PARTITION BY customer_id
        ORDER BY order_time, order_id
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS cumulative_spend
FROM orders;
⏱ Complexity
Requires ordered partitions; avoid self-join quadratic logic.
👑 Principal signal
Specify ROWS vs RANGE semantics when duplicate timestamps exist.
SQLAnti-joinS4

Customers who never ordered

Problem: Return customers with no orders.

🐢 Brute force first

Nested NOT IN can be error-prone with NULL semantics.

💡 Hint

NOT EXISTS or LEFT JOIN ... IS NULL.

💻 Optimized solution
SELECT c.*
FROM customers c
WHERE NOT EXISTS (
    SELECT 1
    FROM orders o
    WHERE o.customer_id = c.customer_id
);
⏱ Complexity
Physical cost depends on indexes/optimizer; conceptually an anti-join.
👑 Principal signal
Mention NOT IN + NULL pitfalls and inspect join-key quality/cardinality.
SQLLAGS5

Sessionize clickstream with 30-minute gap

Problem: Start a new session whenever an event is more than 30 minutes after the previous event for the same user.

🐢 Brute force first

Self-join every event to search for previous event.

💡 Hint

LAG to calculate previous timestamp, then cumulative SUM of new-session flag.

💻 Optimized solution
WITH x AS (
  SELECT
      e.*,
      LAG(event_time) OVER (
          PARTITION BY user_id
          ORDER BY event_time
      ) AS prev_time
  FROM events e
),
flags AS (
  SELECT *,
      CASE
        WHEN prev_time IS NULL
          OR event_time > prev_time + INTERVAL '30 minutes'
        THEN 1 ELSE 0
      END AS new_session
  FROM x
)
SELECT *,
    SUM(new_session) OVER (
        PARTITION BY user_id
        ORDER BY event_time
        ROWS UNBOUNDED PRECEDING
    ) AS session_id
FROM flags;
⏱ Complexity
Window ordering dominates.
👑 Principal signal
Discuss late/out-of-order events and whether event-time reprocessing changes historical sessions.
